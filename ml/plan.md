Внедрение ML-модели в ваш текущий проект на Next.js потребует создания микросервисной архитектуры. Поскольку Next.js работает на Node.js, а машинное обучение — это экосистема Python, лучшим решением будет разделить их.

Ниже представлен подробный пошаговый план интеграции: от обучения модели до появления интерфейсов в вашей системе. Этот план можно смело переносить в практическую главу вашего диплома.

### Этап 1. Подготовка и обучение модели (Офлайн)

На этом этапе вы создаете "мозг" вашей системы. Это делается вне основного веб-приложения.

1. **Сбор данных:** Вы пишете SQL-скрипт для выгрузки данных из вашей `db/base.db` (таблицы пользователей, тестов, результатов) в CSV-файл или используете открытый датасет (например, OULAD), подогнав его структуру под вашу БД.
2. **Обучение (Jupyter Notebook):** Вы используете скрипт из предыдущего ответа для обучения моделей XGBoost (прогнозирование риска) и KNN (рекомендации).
3. **Сохранение артефактов:** С помощью библиотеки `joblib` или `pickle` вы сохраняете обученные модели в файлы: `xgboost_model.pkl`, `shap_explainer.pkl` и `knn_model.pkl`. Теперь модель готова к переносу на сервер.

### Этап 2. Разработка ML-микросервиса (FastAPI)

Вы создаете небольшое отдельное приложение на Python, которое будет "слушать" запросы от вашего Next.js.

1. **Создание структуры:** Рядом с папками `src/` и `db/` создаете папку `ml_service/`.
2. **Написание API:** Пишете файл `main.py` на FastAPI.
   - При старте сервера загружаются файлы `.pkl`.
   - Создается эндпоинт `POST /api/predict`.
   - Он принимает JSON с характеристиками студента (средний балл, время, просроченные дедлайны).
   - Возвращает JSON: `{"risk_score": 0.85, "reasons": ["Низкий балл по SQL"], "recommendations": [id_теста_1, id_теста_2]}`.
3. **Запуск:** Сервер запускается локально на порту `8000` (в то время как Next.js работает на `3000`).

### Этап 3. Обновление базы данных (SQLite)

Чтобы не опрашивать Python-сервер каждую секунду, результаты аналитики нужно кэшировать в вашей базе `db/base.db`.

1. В файл `lib/init-db.ts` добавляете новую таблицу `AnalyticsData` с полями: `user_id`, `risk_probability` (FLOAT), `reasons` (TEXT/JSON), `last_updated` (TIMESTAMP).
2. Создаете связующую таблицу `StudentRecommendations`, где будут храниться связи `student_id` -> `recommended_discipline_id`.

### Этап 4. Бэкенд-интеграция в Next.js (API Routes)

Теперь нужно научить ваш текущий бэкенд общаться с Python-сервисом.

1. Создаете новый эндпоинт в Next.js: `src/app/api/student/[id]/analytics/route.ts`.
2. **Логика роута:**
   - Делает `SELECT` из вашей базы SQLite, собирая агрегированную статистику по конкретному студенту `[id]`.
   - Делает внутренний HTTP-запрос (через `fetch`) к `http://localhost:8000/api/predict`.
   - Получает ответ от ML-модели, парсит JSON.
   - Записывает результат (риск и причины) в SQLite.
   - Возвращает данные на клиент (фронтенд).
3. Настраиваете `CRON`-задачу или триггер, который раз в день (или при завершении теста) пересчитывает эти риски для всех студентов.

### Этап 5. Интерфейс преподавателя (СППР в действии)

Реализация визуальной части для лица, принимающего решения.

1. **Список студентов (`src/app/teacher/discipline/[id]/group/[groupId]/page.tsx`):**
   - Добавляете колонку "Статус риска".
   - Студенты с риском >70% подсвечиваются красным значком (⚠️).
2. **Карточка студента (Модальное окно):**
   - При клике на студента открывается дашборд.
   - **Блок "Диагностика" (SHAP):** Выводятся текстовые причины (например, "Риск отчисления высок из-за систематических пропусков тестов").
   - **Блок "Принятие решения":** Система предлагает кнопку _"Рекомендовать курс: Основы баз данных"_.
3. **Действие:** При нажатии на эту кнопку срабатывает ваш текущий API (например, `src/app/api/assign-test/...`), который назначает студенту корректирующий материал. Преподаватель совершил действие с опорой на ИИ.

### Этап 6. Интерфейс студента (Адаптивное обучение)

Изменения в личном кабинете ученика.

1. **Главная страница (`src/app/dashboard/page.tsx`):**
   - Добавляется новый UI-компонент: виджет "Индивидуальные рекомендации".
   - Виджет делает `GET` запрос к вашему API, читает рекомендации из базы и показывает карточки курсов/тестов с пометкой _"Подобрано для вас ИИ для устранения пробелов"_.
   - Кнопка "Начать тестирование" перенаправляет на существующий роут `src/app/test/[id]`.

### Этап 7. Развертывание (Docker)

Поскольку проект теперь состоит из двух сервисов (Node.js и Python), в дипломе (в разделе "Развертывание") вы описываете `docker-compose.yml`.

- Контейнер `web`: ваш Next.js интерфейс.
- Контейнер `ml-api`: ваш FastAPI сервис.
  Они будут общаться друг с другом по внутренней сети Docker.

Такой план демонстрирует комиссии, что вы не просто "прикрутили нейросеть", а спроектировали полноценную микросервисную архитектуру, решающую конкретную бизнес-задачу учебного заведения.
